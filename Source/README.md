# ソース構成と分割の目安

フォームには画面状態、入力の適用、選択、再生と工程操作を置く。画面の生成、属性欄の再利用、描画、ページ配置、出力結果の表示は、それぞれを説明できる部品へ分ける。

1,000行は分割を検討する目安であり、厳密な上限ではない。関連する操作がまとまっている場合は多少超えても維持する。行数だけを減らすための分割や、互いの内部状態へ依存する断片への分割は行わない。1フォルダにPascalユニットが10個を超える場合は、責務ごとのサブフォルダを検討する。フォームの `.pas` と `.dfm` は同じ場所に置く。

## 分離した部品の境界

- `TRigmEditorProperties` は属性欄の索引・再利用・候補一覧を管理する。文書を借用し、文書置換時に古い候補参照を解除する。入力の適用とUndoは編集フォームから既存の編集器へ委譲する。
- `PaintCharacterPreview` は表示状態のレコードを受け取り、画像・ボーン・メッシュを合成する。入力イベントと画像キャッシュは編集フォームが管理する。
- `TRigmMovieControls` は所有フォームへコントロールを生成し、操作側のコールバックを配線する。作品の下書きや再生状態は編集フォームが保持する。
- `TRigmMoviePropertyPages` はページ別の配置・スクロール・フォーカスを管理する。入力内容や作品revisionは変更しない。
- `TRigmMoviePreview` は表示フレームを所有し、倍率とパンを保存モデルから分離する。配置の確定は共通セッションのrevision・編集リース検査を通す。
- `TRigmMovieExportFeedback` は既存ジョブを監視し、進捗・エラー・確認済み完了パスを表示する。出力開始と下書きの適用判断は編集フォームが担当する。

VCLコントロールの所有者は従来どおりフォームまたは親コントロールとする。分離した通常オブジェクトはその参照を借用し、フォームが所有して先に破棄する。旧 `RigmMovieForm` のプレビュー型とメニュー入口は互換性のため維持している。
