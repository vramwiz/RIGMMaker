# 自動制作の実装・検証（2026-10-15）

## 現在の動作

Dots用パイプから`app-auto-start`へ入力書式の全文を送ると、種類別の最新台本をコピーし、台本・総評・配役・表情・音声・字幕・シーン画像・サムネイル・MP4・投稿用テキストまで進める。既存Codex用パイプも同じ命令処理を使用する。方式は起動時に選び、同時には通信しない。

| command | args | 結果 |
| --- | --- | --- |
| `app-auto-validate` | `text` | 不足・不正の全件と正規化データ |
| `app-auto-sources` | `scriptType` | 種類別候補、除外理由、最新`selected` |
| `app-auto-source-check` | `scriptType`, `projectId` | 個別の候補可否・最新選択・保存しないGUIコピー検証 |
| `app-auto-check` | `text` | コピー元・同梱DLLの事前検査のみ。`ready`でも制作未開始 |
| `app-auto-start` | `text` | 非同期の制作受付と`jobId`。入力不正は`invalid`、コピー元なしは`blocked` |
| `app-auto-status` | `jobId`, 任意の`afterSequence` | 状態、進捗通知、完成ファイルのパス・SHA256。画像・表情処理中は`currentTask`、MP4処理中は`currentJob` |
| `app-auto-cancel` | `jobId` | 中止要求。停止完了まで状態取得を続ける |

`start`に入力不足があればコピーや生成を始めない。稼働中の二重開始と、他のパイプ編集命令は拒否する。`events`の`sequence`は単調増加し、最後に受け取った番号を`afterSequence`へ指定すれば通知を重複表示しない。状態取得には毎回新しい通信request idを使う。

制作の最終状態は`completed`, `failed`, `cancelled`。成功判定は`state=completed`かつ`productionCompleted=true`。`busy=false`やMP4開始だけを成功としない。MP4完成を先に通知し、投稿用テキストも保存してから全体完了を通知する。テキスト作成失敗時も完成したMP4は保持する。

## 工程と採用ルール

- 保存済み更新日時で漫画／アニメ別に最新を選ぶ。入力中・編集中・未分類・自動制作の途中／失敗／中止のコピーは除外する。候補がなくても新規制作や別種類へ切り替えない。
- GUIと同じ`CopyScriptDraft`・`NextScriptDraft`で新しいIDへコピーし、元台本のハッシュを記録する。キャラと配置、レイアウト・背景色、解像度・fps・エンコード設定、VOICEVOX接続先・人物・標準状態・保存済み共通値／話者値・該当する音声エフェクトを引き継ぐ。
- コピーの共通前段・締めセリフは保持。本題は入力データへ置き換える。固定5項目の総評は入力された0～5の点数と本文を使用する。説明役はコピーした配役の先頭の有効キャラへ割り当て、実素材を対象にAIの表情判定を行う。
- 本文と字幕と読み上げ文は同じ文章。音声生成が成功して現在の本文に一致すれば自動制作では試聴を待たない。人間が聞いたことを示す`VoiceHeardKey`は付けない。自動制作メタデータのない通常台本の試聴ルールは維持する。
- 入力シーンごとの区切りを原稿offsetから再現する。改行は同じ入力シーンにまとめる。総評の複数行は1つの独立チャートシーンへ割り当てる。`表示`は画像下へ表示する。
- 背景→通常シーン→サムネイルの順で生成し、検査して自動採用・保存する。破損画像や要求ID・指紋の不一致は拒否する。サムネイルには選択キャラの実ファイルから用意した透過PNGと確定済みシーン画像を渡す。
- 前段・締めの補助画像は引き継いだセリフを指示に使う。固定エンド画像が元台本で指定済みなら保持し、未指定の任意画像は省略する。必須サムネイルは既存生成ルールを使用する。
- 投稿用TXTはタイトル、概要、既存の親作品情報を空行で区切った1ファイル。作品情報が確定していない場合、入力作品名・任意URL・総評本文から概要を構成する。作者などの調査結果を推測で埋めない。URLへのアクセス・作品情報の自動調査は今回の処理に含めない。

## Dotsからの使い方

Dotsには、このフォルダの`note.md`・`パイプ仕様.json`・入力済み台本TXTを読ませる。実行できるホスト上で次の起動手順を使う。

```powershell
$repo = 'D:\DelphiProg\MyApp\RIGMMaker'
$launch = & "$repo\制作支援\パイプ\Start-RigmCommunication.ps1"
$sender = "$repo\制作支援\パイプ\Send-RigmDotsCommand.ps1"
$text = [IO.File]::ReadAllText("$repo\自動制作\台本\通し試験.txt")
$reply = & $sender -ConnectionFile $launch.connectionFile -Command app-auto-start `
  -ArgsJson (@{text=$text}|ConvertTo-Json -Compress)
$jobId = $reply.data.jobId
# runningの場合、以降はapp-auto-statusだけを新しい通信idで繰り返す。
& $sender -ConnectionFile $launch.connectionFile -Command app-auto-status `
  -ArgsJson (@{jobId=$jobId;afterSequence=0}|ConvertTo-Json -Compress)
```

2026-10-16以降、通常のRIGMMaker.exeを引数なしで起動すればDots用JSONLパイプが開く。上の起動スクリプトも既定で同じ通常EXEと通信方式を使う。利用者に特別な引数や専用起動ファイルを要求しない。起動済みなら現在のプロセスの接続情報を使い、二重起動しない。接続情報のtokenを要求へ必ず付ける（専用送信器は自動付与）。生のトークンを学習データへ保存しない。リモートDotsからの起動には、Dots側がそのWindowsホストで起動コマンドを実行できる機能が必要。停止中のアプリへパイプだけで接続することはできない。
