# 動画制作の現行仕様

対象EXEは `RIGMMaker.preview.exe`。通常はCodex / dotと共通パイプを使い、GUIと同じプロジェクトデータを工程ごとに調整する。生成完了後も工程に留まり、GUIまたはパイプから明示的に次へ進む。人間の毎回の確認済みフラグは要求しない。

新規プロジェクトはFullHD1920×1080。fps30は既存FullHDプリセットの値であり、今回ユーザーはfpsを指定していない。既存ファイルの明示された寸法・fps・その他設定は保持する。既存RIGM素材は独立して読み込み、元ファイル・未保存RIGM文書・手動役割・ロックを変更しない。RIGM open時の自動再判定と本当の必須パーツ不足による停止を維持する。

## 工程と共通パイプ

既存5工程は `script` → `setup` → `audio` → `preview` → `export`。出力後に明示的に次へ進めると `complete` になる。

- `movie-workflow-status`: 現在工程・可能操作・未完成理由・必要な再生成・実成果参照を返す。
- `movie-workflow-run`: 現在工程の結果だけを作る。台本取込、接続/素材/声の診断、未完成音声生成、演技プレビュー、動画出力に対応する。
- `movie-workflow-next`: 最新projectId/revisionと実際の工程条件を満たす場合だけ一工程進む。不足時は現在状態とneedsを返す。
- `movie-workflow-back`: 一つ前、または指定した前工程へ戻る。前進の飛び越しには使わない。

`currentStage`、`canRun`、`canNext`、`needs`、`allowedCommands`、`regenerate`、`results` をGUIとパイプで共有する。音声の再生成対象は声と本文のfingerprint、プレビュー/動画は内容と参照ファイルの同一性で判定する。字幕・演技変更だけでは既存音声を再生成しない。参照が消失・変更した結果を現在の結果として扱わない。

GUIの通常操作は「工程の結果を作る」「次へ」「前の工程へ」と現在工程・結果プレビュー・編集。デバッグ詳細や従来の個別ツールバー操作は保持する。複雑な新画面を追加しない。

動画APIは計41命令。更新と工程操作には最新 `movie-status.projectId/revision` が必要。PowerShell送信器は省略された識別情報を補う。GUIは表示したリビジョンで編集を適用し、未適用入力を保持する。別操作が先に更新した場合は上書きを拒否し、明示的な最新データ読込で再調整する。ジョブは独立スナップショットで動作し、開始後に変わったプロジェクトの古い結果を適用しない。

## 保存・再開と既存形式

`RIGM-MOVIE` formatVersion=1、拡張子 `.rigmovie` を維持する。安定したcue id、話者・本文・字幕・間・表情・動作・背景・parameters・acting・音声参照/fingerprintに、工程位置とプレビュー/動画参照・同一性情報を保存する。工程情報のない旧ファイルはscript工程から開き、既存設定を保持する。

生成結果と工程移動は未保存状態で保持し、自動保存しない。明示的なmovie-saveでRIGM/WAV/LAB/背景/プレビューを隣接.assetsへ保存し、再開時に内容を再判定する。動画は元の実ファイル参照を保持する。キャンセル・失敗時にも完成済み音声を保護し、同工程で未完了部分を再生成できる。出力は既存AVI/MP4/PNGを上書きしない。

actingの既存範囲・素材優先/変形・既存差分選択・音声と演技の分離、PCM波形、AVI MJPEG/48000Hz PCM16 mono、任意の既存FFmpegによるMP4 H.264/AACを維持する。既存素材にない自然な横顔や表情を生成しない。MP4は一時AVIを使うため2GB上限がある。

## 任意の一括制作

`movie-produce`、`movie-production-status/resume/cancel` は互換・任意用。一括APIを明示的に選んだ場合だけ診断→音声→プレビュー→動画出力を連続実行する。通常の工程ごとの経路では使わない。requestKeyによる現在セッション内最新64件の再送保護と、完成音声の保持を維持する。

## 検証と実環境の状態

最終Win64 Debug/Releaseと1562項目の検証が成功。工程テスト66項目は共通パイプ→GUI修正→次へ/戻る、再生成、未適用入力保持、古いrevision/job拒否、保存再開を含む。通常経路と任意一括APIを別に検証した。ユーザーのPerMonitorV2設定と既存DPI補正を保持し、両EXEの埋込manifestを確認した。
